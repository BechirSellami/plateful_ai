LLM Planner Flow

How PlannerAgent._plan_llm() derives an execution plan from a user message

entry User Message Received
WebSocket delivers state.messages[-1]["content"] to plan().
Session carries forward meal_plan, menu_items, and recommendations from prior turns.
build Assemble System Prompt
_build_system_prompt(available_agents, meal_plan) injects:
Prompt components
  • Agent catalog — descriptions of each registered agent (context only; LLM does not pick agents)
  • Intent guide — 9 intent definitions with examples
  • Constraint schema — typed fields including food_keywords and cuisine distinction
  • Compound flags — has_preference detection signals ("I love", "I'm allergic", etc.)
  • Meal plan context — active plan days or "no active plan"
  • Out-of-scope rules — reject weather, jokes, taxes, etc.
  • Output schema — {"intent", "constraints", "compound_flags"} — no plan field
🧠memory
📋menu
⭐recommendation
📅mealplan
🛒execution
💾learning
llm call Claude API Request
anthropic_client.messages.create() with model claude-sonnet-4-20250514, max_tokens=512.
Wrapped in a Langfuse generation span (planner.llm) recording input/output tokens and latency. Falls back to null_llm_trace() if Langfuse is disabled.
parse Response Parsing & Sanitization
1. Strip markdown code fences (```json … ```)
2. json.loads(text) → {"intent", "constraints", "compound_flags"}
3. Type-check: ensure constraints and compound_flags are dicts
4. Short-circuit if intent == "out_of_scope" — return empty plan immediately
route Compose Plan via flow_router.compose_plan()
compose_plan(intent, available_agents, compound_flags) is the single source of truth for step ordering.

Step 1 — look up INTENT_FLOWS[intent] for the base step list.
Step 2 — filter steps whose agent is not in available_agents.
Step 3 — if compound_flags.has_preference is true AND intent is not declare_preference AND learning is not already in the plan, append learning.

The LLM never picks agents or orders steps — it only classifies.
plan may be empty
decision Is the composed plan empty?
An empty result means the intent had no registered flow steps after agent filtering.
plan has steps
return Execution Plan
Returns {"intent", "constraints", "compound_flags", "plan"}.
plan is an ordered list of {"agent", "reason"} steps.
plan is empty
fallback Keyword Planner
Unknown intent or all steps filtered → fall back to _plan_keyword().

Keyword path uses the same compose_plan() helper, so output shape is identical.
apply Hydrate Workflow State
Back in plan(): write state.intent, merge state.constraints, set state.last_result.
Log plan_created with trace_id, mode, intent, constraint keys, compound_flags, and step list.
observe Planner Span Updated
Both the WebSocket handler (ws.py) and run_planned_workflow update the parent planner span with the full output before closing it:

intent · constraints · compound_flags · plan (agent names list)

The child planner.llm generation span captures the raw LLM response and token counts.
catch-all Exception Boundary
If anything in the LLM path throws (API timeout, JSON parse error, unexpected schema), _plan_llm catches it, logs llm_planner_fallback with exc_info=True, and returns the keyword planner result. Never raises.
output Plan Handed to Orchestrator
run_workflow(flow_def, state, registry) receives the ordered step list.
Agent contracts are validated in warn-mode before execution begins.
Each step streams progress back to the client via WebSocket.

Intent → Agent Steps (source: INTENT_FLOWS)

Steps are composed by compose_plan() in flow_router.py — the LLM only provides the intent and flags. + learning is appended automatically when compound_flags.has_preference = true and the base flow doesn't already end with it.

get_recommendation memory→ menu→ recommendation
order_meal memory→ menu→ recommendation
declare_preference learning
confirm_order memory→ menu→ execution→ learning
create_mealplan memory→ menu→ mealplan
submit_mealplan execution→ learning
ask_question memory→ menu→ recommendation
out_of_scope empty plan — short-circuit with capability message, no agents run
has_preference flag any intent above + + learning if not already present

Constraint Schema (LLM-extracted, passed to menu & execution agents)

budget: int Maximum spend in USD, e.g. 20 from "under $20".
cuisine: string Cuisine origin only — e.g. "thai", "italian". Never a food item name.
food_keywords: list[string] Specific food items or types — e.g. ["pasta", "sandwich"]. Used for name/description substring search when the user mentions a food that isn't a cuisine. Supports OR logic across multiple keywords.
dietary: string Restriction, e.g. "vegetarian", "vegan", "halal", "keto".
meal_type: string "breakfast" · "lunch" · "dinner" · "snack"
selected_item: string Specific item the user chose to order, e.g. "Tofu Stir Fry". Drives execution agent item resolution.
preference: string Stated preference or restriction, e.g. "loves spicy food". Persisted by the learning agent.
