LLM Planner Flow

How PlannerAgent._plan_llm() derives an execution plan from a user message

entry User Message Received
WebSocket delivers state.messages[-1]["content"] to plan().
Session carries forward meal_plan, menu_items, and recommendations from prior turns.
build Assemble System Prompt
_build_system_prompt(available_agents, meal_plan) injects:
Prompt components
  • Agent catalog — descriptions of each registered agent
  • Ordering rules — memory before menu, menu before recommendation
  • Preference detection signals — "I love", "I'm allergic", etc.
  • 10 flow patterns — recommendation, order, meal plan, compound
  • Meal plan context — active plan days or "no active plan"
  • Out-of-scope rules — reject weather, jokes, taxes, etc.
  • Output schema — {"intent", "constraints", "plan"}
🧠memory
📋menu
⭐recommendation
📅mealplan
🛒execution
💾learning
llm call Claude API Request
anthropic_client.messages.create() with model claude-sonnet-4-20250514, max_tokens=512.
Wrapped in a Langfuse generation span (trace_llm_call) that records input/output tokens and latency. Falls back to null_llm_trace() if Langfuse is disabled.
parse Response Parsing & Sanitization
1. Strip markdown code fences (```json ... ```)
2. json.loads(text) into {"intent", "constraints", "plan"}
3. Type-check: ensure constraints is dict, plan is list
4. Filter plan steps to only agents present in available_agents registry
plan may be empty
decision Is the plan empty?
After filtering, if no valid agent steps remain, the planner must decide between out-of-scope (intentional empty) or degraded fallback (LLM produced unusable output).
plan has steps
return Execution Plan
{"intent", "constraints", "plan"}
Plan is an ordered list of agent steps the orchestrator will execute sequentially.
plan is empty
decision Out of scope?
intent == "out_of_scope"?

Yes → return empty plan with out_of_scope intent. Orchestrator short-circuits with a helpful capability message.

No → LLM produced garbage. Fall back to _plan_keyword() deterministic planner.
apply Hydrate Workflow State
Back in plan(): write state.intent, merge state.constraints, set state.last_result.
Log plan_created with trace_id, mode, intent, constraint keys, and step list.
catch-all Exception Boundary
If anything in the LLM path throws (API timeout, JSON parse error, unexpected schema), the entire _plan_llm method catches it, logs llm_planner_fallback with exc_info=True, and falls back to the keyword planner. Never raises.
output Plan Handed to Orchestrator
run_workflow(flow_def, state, registry) receives the ordered step list.
Agent contracts are validated in warn-mode before execution begins.
Each step streams progress back to the client via WebSocket.
